# AI Workbench · 本地程序悬浮台

一个常驻桌面的竖向悬浮条，把你常用的本地 AI 工具收在一处。
点一下图标切换显示/隐藏，拖一下就能调顺序。

---

## 这是什么

如果你电脑上装了好几个 AI 客户端 —— 聊天助手、笔记工具、代码工作区、
本地跑的服务 —— 它们散在任务栏和桌面上，来回切窗口很烦。

这个程序把它们收成一条窄窄的悬浮条，贴在屏幕边缘：

- **一眼看到谁在运行** —— 每条右侧的开关就是那个程序的开/关
- **点图标直接唤到前台**，不用在任务栏里翻
- **拖动就能换顺序**，常用的排上面
- **收进托盘不碍事**，点右上角 × 只是藏起来，程序还在跑

技术上是个 Electron 应用，主要特点：

- **图标自动提取** —— 加一个 exe 就完事，不用手动挑图标文件。
  提取是纯 JS 实现的（自己解析 `.ico` 和 exe 的 PE 资源表），
  **不依赖 Python，也不依赖 Pillow**
- **便携运行** —— 数据存在 exe 旁边的 `data/` 目录，整个文件夹拷走就能用
- **本地优先** —— 只访问 `127.0.0.1`，不联网上报任何东西

## 快速开始

### 直接用

1. 下载或打包出可执行文件
2. 双击 `AI-Workbench.exe`
3. 点右下角 **「+ 添加文件」**，选一个你常开的 exe

就这样。图标会自动抽出来，程序会自动出现在列表里。

### 自己打包

```bash
npm install
npm run release
```

产物在 `dist/AI-Workbench/`，整个文件夹就是便携版：

```
AI-Workbench/
├─ AI-Workbench.exe    ← 主程序，双击这个
├─ resources/           ← 程序资源，别改
├─ data/                ← 你的配置和图标（拷走会一起带走）
├─ logs/                ← 运行日志
└─ 启动.bat             ← 备用启动器，一般用不上
```

### 开发模式

```bash
npm start
```

## 怎么用

| 操作 | 效果 |
| --- | --- |
| 点条目上的**图标** | 程序在跑就最小化，没跑就置顶到前台 |
| 点条目上的**开关** | 启动 / 关闭这个程序 |
| **拖动条目** | 调整顺序，松手就记住 |
| 右键条目 | 重建图标 / 删除 |
| 点右上角 **×** | 收进托盘（**程序还在跑**，托盘图标能叫回来） |
| 托盘图标左键 | 显示 / 隐藏悬浮条 |
| 托盘图标右键 | 置顶 / 失焦自动隐藏 / 退出 |
| 齿轮图标 | 设置唤出悬浮条的快捷键 |

真要退出程序：**托盘右键 → 退出**。

## 配置格式

程序条目是 `plugins/` 下的 JSON，一个文件一个程序：

```json
{
  "id": "my-app",
  "name": "我的应用",
  "short": "我",
  "color": "#534AB7",
  "type": "app",
  "enabled": true,
  "launch": {
    "path": "D:/Apps/MyApp/MyApp.exe",
    "args": [],
    "workdir": "D:\\Apps\\MyApp"
  },
  "find": {
    "process": "MyApp.exe"
  },
  "hotkey": ""
}
```

几个要点：

- `find.process` —— 用来定位窗口的进程名，**要和任务管理器里看到的一致**
- `launch.pathGlob` —— 版本号会变的程序用它，支持通配：
  `"D:/Apps/MyApp/*/MyApp.exe"`
- `hotkey` —— 全局快捷键，留空即可。想让某个程序有启动键才填，格式 `Ctrl+Alt+7`
- `type: "webview"` —— 背后是本地 HTTP 服务的程序，用 `url` 指定地址、
  `probe.port` 指定端口

**路径可以写占位符**，换机器不用改配置：

| 占位符 | 指向 |
| --- | --- |
| `${app}` | 程序目录 |
| `${res}` | 资源目录 |
| `${server}` | 内置工作台服务目录 |
| `${home}` | 用户主目录 |

## 图标是怎么来的

程序图标没有统一位置，所以按「越往后越差」的顺序试：

| 顺序 | 来源 |
| --- | --- |
| 1 | 快捷方式 `.lnk` 里指定的图标 |
| 2 | 程序目录里的图标文件（`resources/`、`assets/`、Flutter 的 `data/flutter_assets/assets/` 等） |
| 3 | exe 内嵌图标（解析 PE 资源表，取最大尺寸那张） |

第 2 步有个坑：目录里常混着 `canvas.ico`、`md.ico`、`base.ico` 这种**文件类型图标**，
按「文件更大」来挑一定挑错。所以只接受名字明显像应用图标的
（`icon` / `app` / `logo` / 程序名本身），匹配不上就直接用 exe 内嵌的那张。

**全部纯 JS 实现**：

- `.ico` —— 读文件头 → 目录项 → 取面积最大的那张；数据是 PNG 就直接用，
  是 DIB 就自己按 BGRA 翻转、还原 AND 掩码，再用 zlib 包成 PNG
- `.exe` —— 解析 PE 头 → 节表（RVA 换算文件偏移）→ 资源表 →
  `RT_GROUP_ICON` 取最大尺寸组 → `RT_ICON` 取图像数据

> 之前这条链是调 Python 做的，而很多用户的 Python 并没装 Pillow，
> 于是图标一直提取失败，只能退化成 48px 的通用白框。
> 改成纯 JS 之后，图标提取跟机器上装没装 Python 完全无关。

图标文件丢了会自动补，三道兜底：启动时、添加文件时、界面渲染时。

## 代码结构

```
main.js              主进程入口：只做装配，管窗口、托盘、IPC
modules/
├─ paths.js          路径常量与占位符（数据目录、便携模式）
├─ plugins.js        程序条目的增删改查与排序
├─ icons.js          图标提取（纯 JS，不依赖 Python）
├─ launcher.js       启动 / 退出程序
├─ winmgr.js         Python 定位与 winmgr.py 调用
├─ settings.js       设置读写
├─ logger.js         日志
└─ proxy.js          清掉代理（只连本机，不需要代理）
renderer/            悬浮条界面
winmgr.py            Win32 窗口管理（找窗口、置顶、读位置）
```

模块之间靠**依赖注入**连接，不共享全局状态，所以每个模块都能单独加载、
单独测。加新功能时照着这个模式来，别往 `main.js` 里堆。

## 为什么需要 Python

只有一处：Windows 上按进程名找窗口、读窗口位置、置顶这些操作，
Node 没有直接 API，只能调 Win32。`winmgr.py` 用 ctypes 干这件事，零第三方依赖。

**图标提取完全不用 Python**（见上一节）。

程序会自动在常见位置找 Python，找不到的话窗口控制功能不可用，
但图标和界面照常工作。

## 常见问题

**点 × 之后程序还在跑？**
故意的。× 只是收进托盘，托盘图标能叫回来。
真要退出：托盘右键 → 退出。

**双击 exe 什么都没发生？**
检查环境变量 `ELECTRON_RUN_AS_NODE` 有没有被设成 `1`。
被设了的话程序会退化成纯 Node 模式，不报错就退出。
`启动.bat` 已经处理了这个，手动在命令行启动则要 `env -u ELECTRON_RUN_AS_NODE ./AI-Workbench.exe`。

**图标是白色方框？**
图标提取失败。程序会自动重试；也可以右键条目选「重建图标」。
跑 `data/_icon.log` 能看到具体卡在哪一步。

**改了配置没反应？**
右键托盘图标选「重新载入」，或重启程序。
